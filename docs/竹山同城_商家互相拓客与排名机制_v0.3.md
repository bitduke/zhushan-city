# 竹山同城：商家互相拓客与排名机制 v0.3

> 2026-11-20。根据用户最新补充：各店之间可以直接购买拓客服务，并加入排名。本文件细化商家合作市场与榜单；便民信息、社区、活动等其他产品方向继续作为原产品的组成部分。排名和报价规则为设计建议，具体数字未经过经营验证。

## 1. 商业关系修正

**每家店都可以购买其他店的推广服务，也可以通过自己的门店入口为其他店引流并获得约定报酬。** 平台提供合作发布、选择、授权、优惠券、来源记录、效果核对、排名和对账。平台可另行提供代运营服务，也可由商家自行合作。

- A 服装店：提供真实到店顾客可见的福利码和店员推荐。
- B 美业店：希望获得新客，向 A 购买券展示或有效到店服务。
- C 足浴店：同样可以向 A 购买推广，也可以在自己店里为 A/B 引流。
- 居民：领取 A 当场券，主动选择 B/C 的券，自主决定是否到店消费。

这里交易的是推广位置或可核对的引流服务；居民的名单、联系方式和消费决定不作为店与店之间买卖的商品。

## 2. 一条完整的合作流程

1. B 发布拓客合作：项目/优惠券、希望覆盖的地区和合作店品类、周期、预算、计费方式、结算条件。
2. A 查看合作机会与报价，决定是否申请或接受；B 可指定渠道店。双方同意后形成合作单。
3. A 的福利页上架 B 的券；A 自己的券保留在本店位置。A 控制本页合作店名单，平台审核内容和规则。
4. 顾客从 A 的码进入，领取 B 的券；服务端把券、合作单、入口 A 和承接 B 绑定。
5. 顾客到 B，按项目要求完成预约或直接到店，B 员工核销并记录约定的有效结果。
6. 平台按合作单生成可核对的账单；双方核对、处理取消/退款或异常后，确认应付与实付。
7. 合作结果进入相应统计与榜单，帮助下一轮选择合作方；B 可以继续购买，A 可以调整合作对象。

商家小规模时可直接选择对方并发起合作；有稳定合作数据后再开放合作广场，不需要一开始就做复杂竞价系统。

## 3. 两类计费按合作单分别选择

| 方式 | 买方买到什么 | 卖方必须交付什么 | 需要核对什么 |
|---|---|---|---|
| 按位置与周期 | A 店福利页某个推广位、约定天数及物料展示 | 按约定上架和展示；如约定店员介绍，写清执行要求 | 展示是否履约；不承诺固定新客数量 |
| 按有效新客结果 | 经约定规则认定的新客到店/消费 | 从 A 来源引导的顾客在 B 完成约定事件 | 新客口径、去重、时间窗口、取消退款、预算上限 |

同一合作单采用一种主要计费依据。若有位置费与效果费组合，要分别说明各买到什么，由双方明确接受。

**金额示例，仅用于解释资金关系：**B 约定每个合格新客结果总付 20 元，平台服务费包含在其中、为 10%，则每个结果 A 应收 18 元、平台应收 2 元。10 个有效结果对应 B 支出 200 元、A 应收 180 元、平台应收 20 元。B 自己还需承担优惠和实际服务成本；本例没有证明 B 或平台一定盈利，也不是最终报价。

结算资料与真实收付分开记录。线上资金流采用何种支付与结算方式，需按实际商户身份、支付产品和业务责任设计；本轮明确合作账单与费用口径，不默认建立平台余额、充值池或自动提现功能。

## 4. 排名按使用对象设计

### 4.1 商家引流贡献榜

用途：B 选择哪些门店值得购买推广；A 展示自己的引流成绩。

- 默认地区/品类可选，展示最近 30 天结果与统计起止时间。
- 核心指标是约定条件成立的、去重且排除退款/异常的有效新客结果数；同时显示所带来的目标商家数量和争议状态。
- 扫码、领券和核销各自展示，不能把它们相加当成贡献分。
- 可切换查看“有效新客数”和“转化率”。转化率附分母与样本量；样本不足标明，不用 1 人领取、1 人核销的 100% 排名压过有稳定记录的渠道店。
- 新店显示“新加入/暂无足够数据”，提供试合作入口，避免没有历史数据就永远无法被选择。

### 4.2 商家合作机会列表

用途：A 决定推广哪家 B/C 的券。

- 列表显示每个合格结果的报价、有效条件、剩余预算、合作周期、目标客群、接待能力和付款约定。
- 可按“单次报价”“历史合作结果”“距离/适配品类”等排序，分别说明依据。
- 佣金高只说明报价高。是否值得接，还要看优惠是否吸引人、实际转化、是否认账付款及顾客投诉。
- 初期使用清楚的单指标排序和人工选择，不拼凑未经验证的综合分。

### 4.3 顾客看到的优惠和店铺排序

用途：让顾客找到合适、可兑现的本地优惠。

- A 店福利页首屏保留本店权益；合作券按双方授权、用户需求、地点、可用时间等展示，顾客可进入全部商家页自主查找。
- 热门或口碑榜明确统计周期、样本数和口径；消费/核销相关评价与一般评论标注来源区别，保留投诉处理状态。
- 有付费排序或竞价推荐的位置，明确标“广告”，展示规则对合作商家可见。付费高低不能被包装成顾客满意或服务质量的排名。

参考：[《互联网广告管理办法》第九条](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/fgs/art/2023/art_d93a579afd45413e8576e4623fab348f.html)要求竞价排名商品或服务显著标明“广告”，与自然搜索结果区分。

## 5. 结果必须可归属、可核对

- “第一次在小程序领券”不自动等于“第一次到这家实体店消费”。新客需要按合作单口径，由商家确认并保留必要的核对依据；统计明确标注这一来源。
- V1 建议在领取目标券时绑定该次有效来源与合作单。用户已有同一券时，不因再次扫别家码而覆盖既有来源；复杂多触点归因另行设计。
- 同一居民、同一目标商家在约定新客期内只能产生一次合格新客结算。平台可记录后续复访，但不重复当作新客收费。
- 店员自刷、重复核销、无实际约定服务、已取消或退款的无效结果从应付账单和相应榜单中扣除，并提供申诉记录。
- 预算和名额在活动开始前固定。按效果计费时，要明确“领取时占名额还是核销时占名额”，并预留已发出合格权益的结算能力；预算用完停止继续接入新的收费名额，已发券权益按承诺处理。
- 平台记录来源归因，不因此宣称已经证明因果增量。已有顾客自然到店与真正被活动促成的新客，在经营复盘中仍需区分。

## 6. 新增的小程序能力

| 模块 | 功能 | 交付目标 |
|---|---|---|
| 我要拓客 | 发布合作目标、券、费用、周期、预算与新客规则 | B 能清楚地发布购买需求 |
| 我要帮店推广 | 看合作机会、筛选排序、申请/接受合作 | A 自主选择愿意承接的项目 |
| 我的合作 | 已发起/已承接、双方确认、暂停/到期 | A/B 的合作责任和版本一致 |
| 福利页合作券 | 按有效合作单上架和调整顺序 | A 的扫码顾客能看到被授权的 B/C 券 |
| 结果与账单 | 来源、合格结果、待核对、争议、应付/实付 | 商家之间能对账，平台费用清楚 |
| 引流榜 | 近 30 天有效新客、结果样本、地区/品类 | 数据帮助下一次选择渠道店 |
| 合作机会排序 | 报价、条件、剩余预算、历史结果 | A 能比较实际合作价值 |
| 顾客店铺排序 | 附近/热门/可用优惠、清楚标记的广告位 | 顾客理解展示依据与优惠条件 |

## 7. 平台的经营位置

平台收入可以来自合作工具服务费、按有效合作结果收取的技术/交易服务费，以及另行购买的活动执行。选择一种作为早期主收入，按清楚的合同和成本测算确定费率，不把上例的 10% 写成市场事实。

A 获得推荐报酬，摆码与主动介绍的积极性有了具体来源；B 自主选择渠道并控制获客预算；顾客自主获得和使用优惠；平台让匹配、记录与对账更方便。这些共同构成可持续合作的候选机制，仍需用真实履约、付款和复购确认其经济性。

平台长期需要提供的价值是持续可用的合作机会、可信的结果记录、可靠的履约与争议处理，以及便于比较的排名。商家私下也可以合作，因此平台收费须对应这些持续价值，不能只依赖认识了双方。
