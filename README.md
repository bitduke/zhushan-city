已在微信开发者工具模拟器验证的本地流程：

1. 从 A 店福利页领取本店券，新券进入本人券包，出示页显示同一券码。
2. A 店手动输入券码核销，券转为已使用；重复核销返回 4003。
3. 从 A 店页领取 B 店服务券，提交期望时段，B 店演示身份确认预约并标记到店后核销；未预约返回 4007，其他店核销返回 4002。
4. 核销和预约状态保存在本机小程序存储中。商家工作台可切换 A/B/C **演示身份**，用于测试，不代表真实权限系统。
5. B 店可填写按有效新客计费的合作条件，A 店接受后才上架 B 店券。合作券核销生成待核对结果；买方和入口店都确认后才计入账单。线下付款凭据由买方登记、入口店确认实收；本地不转账。
6. 演示榜单只统计双方确认的结果；少于 5 次领券时标记样本不足，不生成名次或转化率。
7. 便民信息提交后进入本地待审队列，审核通过前公开列表不显示；居民可按分类、乡镇和关键词筛选。发布者可查看状态、编辑、下架、申请续期；举报由演示管理台处理并记录操作原因。
8. 新店可提交本地入驻申请，审核通过后才进入公开商家列表；店主可创建、上架和暂停券。门店短 token 能映射到正确商家，同一人五分钟内重复进入只记一次扫码；停用商家后公开页隐藏，已领券显示待处理。
9. 按展位周期的合作在展示期内应付为 0；期满后由买方填写履约依据并确认，才生成固定周期账单。此计费时点由项目发起人于 2026-11-23 选定。
10. 管理台可启停地区与分类；停用后新发布与入驻申请无法选择该项，已审核内容保留等待人工处置。默认地区已整理为竹山县 9 镇 8 乡，正式上线前仍需运营主体核对行政区划。
11. 无效或已停用门店码会显示可返回首页的提示页，不会默默落到某个演示门店。
12. 管理台可以对已审核合作券设置福利页顺序或临时隐藏；隐藏后 A 店福利页不再展示该券，恢复后重新出现，既有已领券不受影响。

新小程序环境已部署 18 个 Active 云函数、33 个集合（含系统集合）、券码唯一约束与主要索引；传统云存储设为 `PRIVATE`。真实微信身份下已走通信息待审/公开/下架、商家入驻审核、扫码去重、本店券领取/重试/核销、预约到店核销、错误店和重复核销拦截，以及两店合作上架与零结果账单；测试内容结束后已下架或停用，公开列表复核为空。本地边界测试 17/17 通过。**小程序码真机扫码、图片跨账号权限、四身份验收和订阅通知仍未完成。**详见 [云端联调清单](docs/CLOUD_READINESS.md)。演示报价不是正式定价。

## 本地闭环演示步骤

1. 在商家工作台切换到奈奈美甲 B 店，打开“拓客合作与对账”，为本店体验券填写报价、平台费用、预算、周期和新客核对条件并发布。价格由测试者填写，界面不预设正式价格。
2. 切换到雅致女装 A 店，在合作页接受这笔合作。打开 A 店福利页 `pages/benefit/shop?shopId=shop_001`，确认 B 券已上架；无合作的 C 券不应出现。
3. 领取 A 店当场券，确认新券进入券包且出示页券码一致；A 店核销后再次输入应得到 4003。
4. 从 A 店页领取 B 店服务券，提交未来时段。B 店在预约页确认并标记到店；此前核销应得到 4007，错误门店核销应得到 4002。
5. B 店核销后进入合作页，先核对“是否有效新客”并填写依据；A 店再确认结果。此时才产生按约定报价计算的应付账单，平台费用与 A 店应收分开显示。
6. B 店填写线下付款凭据，A 店确认实际收到本店应收金额。平台费用的实际收付尚未接入。榜单少量样本不生成名次。

便民信息演示：在“我的”发布一条信息并明确勾选电话公开同意；“我的发布”可见待审状态，公开列表不可见；从“我的”进入**演示管理台**审核通过后，公开列表可搜索到它。举报不会自动下架，管理员处理后才改变公开状态。已公开信息编辑后会暂时下架并重新待审。演示管理台不构成真实管理员授权。

商家演示：从“我的”提交入驻申请，管理台审核通过后公开商家列表可搜索到该店；在商家工作台选择它，创建券草稿并上架。暂停券后停止新领取，已领券保持记录。短 token 可在店铺资料页查看；这是本地映射，正式小程序码尚未生成。

本地演示记录使用小程序本机存储键 `zhushan_mock_core_v1`。清除这个键会重置演示领券、预约、核销、合作和便民信息记录，不影响源码。

## 界面与组件

界面使用 `@tdesign/uniapp@1.0.0` 的按需组件；竹山街坊汇的配色变量在 `src/styles/brand.css`。居民端、商家工作台和运营页使用同一套竹青与暖白配色。线条图标保存在 `src/static/icons/`，可用 `python scripts/generate-ui-icons.py` 重新生成（需 Pillow）。演示数据里的 `picsum.photos` 图片不会作为真实商家图片展示，页面会使用本地图形占位。

首页顶部活动横幅配置在 `src/constants/homeBanners.ts`，图片放在 `src/static/banners/`。当前横幅是平台自有的广告位招商入口，点击进入 `pages/business/advertise`；招商电话与微信号集中在 `src/constants/adContact.ts`。若以后展示付费商家推广，横幅配置项应设置 `isPaid: true`，界面会显示“广告”。

若 `.env.local` 设置 `VITE_USE_MOCK=false`，H5 浏览器无法调用微信云函数；只验收界面时可在当前终端临时设置 `VITE_USE_MOCK=true` 再启动 `pnpm run dev:h5`，无需修改 `.env.local`。

## 版本边界

V1.0 需要可核对的线下合作单与实际收付记录。线上支付、自动分润和提现属于后续版本；完整社区属于 V1.2。早期讨论中的预算托管设想不作为当前实现要求。
